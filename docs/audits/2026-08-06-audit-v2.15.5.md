## 1. Summary

AIFlowBridge 2.15.5 is a mature, local-first glue layer with a clean host-agnostic core, a well-isolated gateway singleton, and a disciplined 3-tier registry plus 4-tier pricing merge.
The three direct vendors (DeepSeek, MiniMax, Xiaomi MiMo) plus the gateway-only OpenRouter path (100+ ids verbatim) are consistently wired through `host-config.ts` -> `providers.ts` -> `gateway/server.ts` with loopback-only binding, SSRF-guarded `baseUrl`, printable-ASCII bearer-key validation, and sanitized session summaries.
The 2.15.x hardening passes (2.14 bearer-key, 2.15 pricing refresh, 2.15.3 dashboard-sort fix, 2.11 SSE caps and size caps) have closed the main audit gaps from 2026-07.
Residual risk is low and concentrated in a single oversized handler (`forwardChatCompletion` ~600 logical lines), one file-lock TOCTOU window, and a few doc/marketing sharp edges rather than architectural flaws.
The marketing positioning around "one OpenRouter key unlocks 100+ models behind a single `http://127.0.0.1:8787/v1` endpoint" is differentiated and defensible, but the README keyword stuffing and the long cost tables dilute the message for skimmers.

## 4. Failles de Securite Possibles

### 4.1 Posture - What is already hardened

- Loopback-only bind (`server.ts:426` `server.listen(..., '127.0.0.1')`) and loopback-only control plane (`probe.ts:32-34` `peerControlUrl` hardcodes `127.0.0.1` even when `baseUrl` is user-controlled).
- SSRF guard on `baseUrl` (`providers.ts:81-93` `isValidProviderBaseUrl` with `BLOCKED_HOSTS` at `providers.ts:26-30`, hex/decimal IPv4-mapped IPv6 normalization at `providers.ts:47-69`).
- Bearer-key shape check before header splice (`server.ts:951-962` guards `resolvedKey` with `isValidBearerKey`, implemented in `bearer-key.ts:41-49` as `1..512` chars of `[\x21-\x7E]`).
- Probe body cap (`probe.ts:49-58` `PROBE_MAX_BODY_BYTES = 4096` on both `Content-Length` and actual `raw.length`).
- Session-summary sanitization before storage (`telemetry/summary.ts:49-58` `sanitizeSummaryText`: `BEARER_RE`, `SK_KEY_RE`, `X_API_KEY_RE`, `LONG_BLOB_RE`, applied before `truncateSummary` at `summary.ts:111`).
- Shutdown token (`server.ts:647-652` `X-AIFlowBridge-Shutdown-Token` check, generated at `server.ts:129` `randomUUID()`).
- API-key redaction in diagnostics (`providers.ts:110-116` `redactProviderForLog`, used at `host-config.ts:520` before `logger.info`).
- SSE guardrails (`server.ts:145-155` `activeSseConnections` cap, `host-config.ts:442-446` `events.maxConnections` 16 / `maxLifetimeMs` 30 min / `includeSummariesInEvents` false default).
- Per-entry size cap and retention (`telemetry/cap.ts:130-164` `enforceEntrySizeCap`, `persistence.ts:392-462` `pruneByRetention`/`pruneInPlace`).

## 6. Ameliorations Possibles (Priorisees)

### 6.1 Must (next minor)

- **Decompose `forwardChatCompletion`.** 600+ lines, 5 distinct responsibilities (body read, provider select, credential resolve, context injection, upstream pipelining). Extract pure helpers so the per-provider semaphore (`acquireProviderSlot` at `server.ts:1061-1089`) and the idle/total watchdog (`resolveUpstreamIdleTimeoutMs` / `resolveStreamTotalTimeoutMs` at `server.ts:1000-1042`) can be unit-tested without binding a real port. Estimated effort 1 day, unblocks the Ollama-vendor addition (same gateway path).
- **Add `0.0.0.0` to the SSRF conversation explicitly.** Document in `providers.ts:15-20` why `0.0.0.0` is left open (bind-all is not a metadata endpoint) so a future contributor does not add it ad hoc and break Docker `--net=host` users.

### 6.2 Should (next 2 minors)

- **Telemetry `byClient`/`bySource` completeness on `removeEntry`.** `persistence.ts:644-679` correctly reverses `byProvider`/`byModel`, but the cross-window mirror does not reverse `byClient`/`bySource` on disk. `telemetry.ts:753-783` does reverse them in-memory, so a peer window that calls `refreshFromDisk` after a delete will re-derive them correctly via `rebuildSnapshot`, but the on-disk `byClient`/`bySource` counts stay stale until retention prune rebuilds. Add symmetric reversal to `revertEntryFromSnapshot` or document that disk `byClient`/`bySource` are eventually consistent.
- **Pricing snapshot freshness surfacing.** `resources/pricing.json:6` `aiflowbridgeVersion: "2.15.5"` and `host-config.ts:534-543` already log `source=... generatedAt=...`. Surface the same stamp in `GET /v1/models` as an `X-AIFlowBridge-Pricing-GeneratedAt` header so external clients (Continue, Open WebUI) can cache intelligently.
- **Standalone hot-reload robustness.** `standalone/context.ts` uses `fs.watch` + 5 s `fs.watchFile` fallback; the Windows fallback interval is not configurable. Expose `AIFLOWBRIDGE_CONFIG_WATCH_INTERVAL_MS` (default 5000) so slow disks can raise it without code change.

### 6.3 Could (backlog)

- **Web-based dashboard at `http://127.0.0.1:8787/dashboard`** (already on `TODO.md` roadmap). Would reuse `buildDashboardHtml` server-side and avoid the webview sandbox that caused the 2.15.3 regression.
- **Ordered failover across vendors** (`deepseek -> minimax -> openrouter` on 429/5xx) - requires careful cost disclosure (the dashboard already groups by provider so the attribution is visible, but the choice must remain opt-in).
- **Property-based test for `deepMergeModel`/`deepMergeVendor`.** The hand-rolled merge in `modelRegistry.schema.ts:526-569` is correct but subtle around `pricing` partials; a fast-check style test would guard against a future field addition that forgets to merge.
